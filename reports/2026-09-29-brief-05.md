## 11. The agent's activity log and its conversations (`18aaa30`, D60)

**Built.**

- **The log.** Claude Code's managed settings, baked into the agent's image and
  read-only to it, set PostToolUse and PostToolUseFailure hooks on every tool.
  The hook sends one line (tool; the path, or the command's first line; ok or
  failed; never contents) to a small logger beside the agent, on dev's network
  only, as the service user, read-only, no capabilities, which alone has the
  log (`/var/lib/allvibe/projects/<p>/agent/log/activity.jsonl`). It takes lines
  only from the agent's address, scans each with the pinned gitleaks and writes
  "(held something that looks like a key or a password: not logged)" when it
  finds one or cannot scan, and writes one line per call. `allvibe agent
  activity <project>`.
- **The conversations.** Only the directory Claude Code writes its transcripts
  to is mounted from the machine, linked into the agent's home; the home, and
  with it the login, stays in memory. `allvibe agent transcripts <project>
  [--delete]`; the delete refuses while the agent runs.
- **Decided** (D60, an amendment to D46): **neither is in backups**, since a
  conversation can hold anything the agent read or was told and backups go off
  the machine for a long time; `agent transcripts --delete` deletes the
  conversations; `project remove` deletes both, and says so first.

**How it was tested without a model.** `test/host/stub-api.mjs` stands in for
the model's API, on dev's network, for one session at a time: the real, pinned
Claude Code runs a real session against it, which asks for four tool calls (a
listing; a file written with a random content marker; a command holding a
random fake key; a command that fails). With an account, which has no login to
use, that session alone is given a random stand-in key.

**Run and seen**, on the test host, in both ways of signing in:

- `test/host/agent-activity.sh`, **29 of 29 with a key and 29 of 29 with an
  account**: one line per call; the written file's path and not its content
  marker; the fake key withheld; the failed call once, as failed; a line from
  dev's app refused (403); a line the agent sent itself with a fake key taken
  and withheld; no log inside the agent; the managed settings read-only to it;
  **the agent's own hook seen running, then turned off with `disableAllHooks`
  in its own and its project's settings, while the log's hook still wrote all
  four lines**; a transcript kept for each session; the directory the service
  user's alone (0700); deleting refused while it runs; and neither the stand-in
  login, the stand-in key nor the vault's values in the log or the transcripts.
- `test/host/agent-isolation.sh`, extended to the logger (from inside it: the
  machine, the router, the device, link-local, prod and the internet refused;
  no Docker socket; only its three mounts) and to the agent's mounts: **89 of 89
  with a key, 88 of 88 with an account**.
- `test/host/agent-leftovers.sh`, extended: the stand-in login and typed text in
  neither the log nor the transcripts, the logger's container gone after stop,
  the transcripts and the log still there: **17 of 17 in both**.
- `test/host/vault-check.sh`, extended: 0 for each value in the agent's kept
  files.
- **Seen failing first:** the new probe against the previous bundle, 11 of 22
  as they must be (the probe then had 22 checks), exit 1.

**Found on the way:** Claude Code calls both hooks for some failed calls, so
the logger gathers a call's events by its id and writes one line. A leak check
first read "3 files" because its pattern file had an empty line, which matches
everything; the values were in none (mistake 38).

**Not verified:** a session with a real model, in either way of signing in; that
is the owner's. **Known limits** (D60): the transcripts keep whatever the agent
read or was told, unscanned; the agent can add lines of its own making, though
it cannot change or delete one; lines are lost if the logger is down; the log
is not rotated.
