## 1. Signing in with a Claude account in the agent (D46, D47, D48)

**Read first, and named in D46:**

- Anthropic's legal page, https://code.claude.com/docs/en/legal-and-compliance,
  read 2026-09-28, quoted exactly in D46.
- Claude Code's "Network access requirements",
  https://code.claude.com/docs/en/network-config, read 2026-09-28: the hosts.
- "Choose a permission mode", https://code.claude.com/docs/en/permission-modes,
  read 2026-09-28: the setting (`permissions.defaultMode`), and that `auto` is
  taken only from the user's or managed settings, never from a project's.
- "Authentication", https://code.claude.com/docs/en/authentication, read
  2026-09-28: on Linux the login is `~/.claude/.credentials.json`, mode 0600.

**Built.**

- `allvibe agent start <project> --sign-in account` (the default stays
  `--sign-in key`, and anything else is refused with the usage line). With an
  account:
  - nothing is unlocked from the key vault and no key file is mounted; the
    container is labelled and told (`AGENT_SIGN_IN=account`) how it signs in;
  - its start writes Claude Code's user settings without `apiKeyHelper`;
  - the gate is started with `ALLOW=api.anthropic.com,claude.ai,platform.claude.com`
    (a running gate with another list is replaced);
  - its last step reads Claude Code's version from its own package file
    instead of running `claude --version` (D48).
- **Both ways of signing in**, in `agent/entrypoint.sh`: `"permissions": {
  "defaultMode": "auto" }` and `"disableClaudeAiConnectors": true`, and the key
  helper only with a key. `PERMISSION_MODE_REVIEWED_WITH` in `src/lib/agent.ts`
  and a unit test make a change of the pinned version fail until the mode is
  reviewed again (D47).
- **Its home**: a tmpfs, as before, with no mount or volume; and now **no swap**
  for the container (`--memory-swap` equal to `--memory`), so nothing in memory
  is written to the machine's swap. I first used the kernel's `noswap` tmpfs
  option: Docker 29 refused it (`invalid tmpfs option "noswap"`), and its
  `--mount` form has no way to pass it either; the swap limit does the same for
  the whole container, and the probe reads it as 0 inside.
- `allvibe agent shell`, with an account, refuses `claude -p`/`--print` and
  refuses to start Claude Code without a terminal:

  ```
  $ allvibe agent shell moods -- claude -p "say hi"
  The agent of moods signs in with your own Claude account, so Claude Code runs there only in a session you drive yourself, in a terminal: never with -p, and never without a terminal (D48).
  exit 1
  $ allvibe agent shell moods < /dev/null
  (the same, exit 1)
  $ allvibe agent shell moods -- git -C /workspace log --oneline -1
  (answers; exit 0)
  ```
- `project status` says which way the agent signs in; `--help` lists the option.
- `test/host/agent-isolation.sh` reads the mode from the agent's label and
  checks both: the gate's list per mode (with an account the three hosts reached
  and fifteen others refused: every other host on Claude Code's list, with an
  example for each of its two wildcard entries, and one on no list; with a key
  the two sign-in hosts refused too); the settings (auto mode, connectors off,
  no way of signing in taken away, the key helper only with a key); the home a
  tmpfs, no mount or volume for it, no volume at all, and swap 0.
- `test/host/agent-leftovers.sh`, new: three random markers kept in `/dev/shm`
  and never on a command line; a stand-in login written into the agent's
  `~/.claude/.credentials.json`; a marker **typed through `allvibe agent shell`
  in a terminal** (a pseudo-terminal from `script`, its record and screen
  thrown away); a control the agent writes to its working copy, on disk. Then
  `allvibe agent stop`, and a search of every file on the machine (all but
  `/proc`, `/sys`, `/dev`), the journal, and Docker's containers and volumes.
